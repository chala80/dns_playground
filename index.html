iQuery and big3d

  • iQuery is XML over TCP port 4353, wrapped in TLS. Trust comes from device certificates exchanged with bigip_add or big3d_install.
  • gtmd on every DNS device opens a connection to big3d on every BIG-IP server it knows, including itself and its sync-group peers. Two DNS devices and two LTMs make 8 connections.
  • big3d sends each result to every gtmd connected to it. A gtmd that loses its connection stops hearing that big3d, so two DNS devices can disagree.

Probers and prober pools

  • The bigip monitor needs no prober. The LTM's own big3d reports its virtual server status.
  • Other monitors (http, tcp, gateway_icmp) need a big3d to send the probe. The server's prober preference picks it, then the fallback if the preference has no available prober.
  • A prober pool is an ordered list of BIG-IP servers. Round Robin spreads monitor instances across members. Global Availability gives them all to the first available member.

About this model

Timing is compressed: one real second is 5 simulated seconds at 1×. Monitor defaults follow BIG-IP DNS (bigip 30 s / 90 s, http 30 s / 120 s). Log lines and iQuery XML are modeled on real /var/log/gtm and iqdump output but simplified, so check a real device for exact message text. Real CLI to try: tmsh show gtm iquery, iqdump 10.1.10.10, tmsh list gtm prober-pool, tmsh show gtm path.
