GSLB on BIG-IP DNS

  • A wide IP is the name (www.example.com). It points to a GTM pool, and the pool's members are virtual servers on BIG-IP server objects, one per data center here.
  • gtmd picks an available member with the pool's load balancing mode and returns its address as the A record. Round Robin alternates. Global Availability uses the first available member in order. Round Trip Times picks the data center closest to the LDNS, using the alternate mode until path metrics exist.
  • If no member is available, the fallback mode applies (return-to-dns here).

bigip and custom monitors

  • bigip sends no probe. The LTM's big3d reports the status of its own virtual servers (from the LTM's pool monitors) to every connected gtmd.
  • Custom monitors (http, https, tcp, gateway_icmp) need a prober: a big3d chosen by the server's prober preference, then its fallback. That big3d probes the virtual server address and sends the result to every connected gtmd.
  • With several monitors on a pool, all must pass (bigip and http_www_health). A pool with no monitor uses the server's monitor, bigip here.

iQuery and big3d

  • iQuery is XML over TCP port 4353, wrapped in TLS. Trust comes from device certificates exchanged with bigip_add or big3d_install.
  • gtmd on every DNS device connects to big3d on every BIG-IP server it knows, itself included: 8 connections here.
  • A gtmd that loses its connection to a big3d stops hearing that big3d's results, so two DNS devices can disagree.

About this model

Timing is compressed: one real second is 5 simulated seconds at 1×. Monitor defaults follow BIG-IP DNS (bigip 30 s / 90 s, custom 30 s / 120 s). Log lines, iQuery XML and the config tab are modeled on real /var/log/gtm, iqdump and bigip_gtm.conf output but simplified, so check a real device for exact text. Real CLI to try: tmsh show gtm iquery, tmsh show gtm pool a, tmsh list gtm monitor, iqdump 10.1.10.10.
